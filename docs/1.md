## 2. Arquitectura Limpia con CQRS

### Capas típicas
```
src/
├── Domain/          # Entidades, Value Objects, interfaces de repos, reglas de negocio puras
├── Application/      # Casos de uso: Commands, Queries, Handlers, DTOs, validaciones
├── Infrastructure/    # Implementación de repos, acceso a datos (EF Core/Dapper), servicios externos
└── API (Presentation)/ # Controllers, middlewares, configuración de DI
```

### Principios clave
- **Dependencia hacia adentro**: Domain no depende de nada; Infrastructure depende de Application/Domain (Dependency Inversion).
- **CQRS**: separar operaciones de escritura (**Commands**) de las de lectura (**Queries**).
  - *Command*: modifica estado, no retorna datos de negocio (o retorna solo el id/resultado de la operación).
  - *Query*: solo lectura, puede usar modelos optimizados de lectura (DTOs, proyecciones), sin pasar por reglas de escritura.
- **Mediator pattern** (ej. librería `MediatR` en .NET): cada Command/Query tiene su propio Handler.
- **Validación** con librerías tipo `FluentValidation`, desacoplada del handler.
- **Repositorios** definidos como interfaces en Domain/Application, implementados en Infrastructure.
- Evitar lógica de negocio en controllers o en la capa de datos.

### "Arquitectura impía" (anti-patrones a detectar y corregir)
- Lógica de negocio dentro de Controllers o Stored Procedures.
- Acceso directo a `DbContext`/SQL desde capas superiores.
- Clases "Dios" (God classes) con demasiadas responsabilidades.
- Falta de separación entre modelos de lectura y escritura.
- Dependencias circulares entre capas.
- Ausencia de interfaces (todo acoplado a implementaciones concretas).

## 3. Comandos de Git (uso normal)

### Configuración inicial
```bash
git config --global user.name "Tu Nombre"
git config --global user.email "tu@email.com"
```

### Flujo básico
```bash
git init                        # Inicializar repo
git clone <url>                 # Clonar repo
git status                      # Ver estado
git add <archivo>                # Agregar archivo al staging
git add .                        # Agregar todos los cambios
git commit -m "mensaje"          # Confirmar cambios
git push origin <rama>           # Subir cambios
git pull origin <rama>           # Traer cambios remotos
git fetch                        # Traer referencias sin fusionar
```

### Branches (feature branches)
```bash
git branch                       # Listar ramas
git branch feature/nombre        # Crear rama
git checkout feature/nombre      # Cambiar de rama
git checkout -b feature/nombre   # Crear y cambiar en un paso
git switch feature/nombre        # Alternativa moderna a checkout
git merge feature/nombre         # Fusionar rama a la actual
git rebase main                  # Reaplicar commits sobre main
git branch -d feature/nombre     # Eliminar rama local (ya fusionada)
git push origin --delete feature/nombre  # Eliminar rama remota
```

### Validar cambios antes/después de commitear
```bash
git status                       # Qué archivos están modificados/staged
git diff                         # Diferencias no staged
git diff --staged                # Diferencias ya agregadas al staging
git log                          # Historial de commits
git log --oneline --graph --all  # Historial visual compacto
git show <commit>                # Ver detalle de un commit específico
git blame <archivo>               # Quién cambió cada línea
```

### Deshacer / corregir
```bash
git restore <archivo>             # Descartar cambios no staged
git restore --staged <archivo>    # Sacar del staging (sin perder cambios)
git reset --soft HEAD~1           # Deshacer último commit, conserva cambios
git reset --hard HEAD~1           # Deshacer último commit y cambios (¡cuidado!)
git revert <commit>               # Crear commit que revierte otro (seguro en remoto)
git stash                         # Guardar cambios temporalmente
git stash pop                     # Recuperar cambios guardados
```

### Conventional Commits (tipos de commit)
Formato: `tipo(alcance opcional): descripción corta`

| Tipo       | Uso |
|------------|-----|
| `feat`     | Nueva funcionalidad |
| `fix`      | Corrección de bug |
| `refactor` | Cambio de código sin alterar comportamiento |
| `docs`     | Cambios en documentación |
| `test`     | Agregar o corregir pruebas |
| `chore`    | Tareas de mantenimiento (configs, dependencias) |
| `style`    | Formato, espacios, sin cambio de lógica |
| `perf`     | Mejora de rendimiento |
| `build`    | Cambios en build/CI |

Ejemplos:
```bash
git commit -m "feat(pedidos): agregar endpoint para crear pedido"
git commit -m "fix(compras): corregir cálculo de descuento"
git commit -m "refactor(kernel): migrar servicio a arquitectura limpia"
```

## 4. Comandos de Docker

### Imágenes
```bash
docker images                     # Listar imágenes locales
docker pull <imagen>:<tag>        # Descargar imagen
docker build -t nombre:tag .      # Construir imagen desde Dockerfile
docker rmi <imagen>                # Eliminar imagen
docker rmi $(docker images -q)     # Eliminar todas las imágenes
```

### Contenedores
```bash
docker ps                          # Contenedores corriendo
docker ps -a                       # Todos los contenedores (incluye detenidos)
docker run -d -p 8080:80 --name miapp nombre:tag   # Crear y correr contenedor
docker start <contenedor>          # Iniciar contenedor existente
docker stop <contenedor>           # Detener contenedor
docker restart <contenedor>        # Reiniciar contenedor
docker rm <contenedor>             # Eliminar contenedor detenido
docker rm -f <contenedor>          # Forzar eliminación (aunque esté corriendo)
```

### Inspección y limpieza
```bash
docker logs <contenedor>           # Ver logs
docker exec -it <contenedor> bash  # Entrar al contenedor
docker inspect <contenedor>        # Detalles de configuración
docker system prune                # Limpiar contenedores/imágenes/redes no usadas
docker system prune -a             # Limpieza más agresiva (incluye imágenes no usadas)
```

### Docker Compose (si el proyecto lo usa)
```bash
docker compose up -d               # Levantar servicios definidos en docker-compose.yml
docker compose down                # Detener y eliminar contenedores/redes
docker compose logs -f              # Ver logs en tiempo real
docker compose build                # Reconstruir imágenes
```
